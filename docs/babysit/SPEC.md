# Architecture Specification: Gemini 4 Argon Babysitting Experiment

## 1. Overview & Objectives

The "Babysitting Argon 4" experiment evaluates the operational behavior, reasoning fidelity, and proxy stability of Google's Gemini 4 Argon (`gemini-4-argon`) agent running against the local `gemini2api` reverse-engineered proxy.

The experiment employs an enhanced 3-role autonomous loop with deterministic semantic invariants:
```
           +-------------------------------------------------------+
           |            Orchestrator (gemini-3.8-flash)            |
           | Generates realistic imperative tasks & seeded fixtures|
           +---------------------------+---------------------------+
                                       |
                                       v
+----------------------------------------------------------------------+
|                     Argon 4 Agent (gemini-4-argon)                   |
|  Executes task turns in an isolated sandbox with tool execution      |
|  Protocols: /v1/chat/completions & /v1/responses (Streaming / SSE)   |
|  Inputs: Imperative prompt + sandbox fixtures + optional vision      |
+--------------------------------------+-------------------------------+
                                       |
                   [Turn Traces & Streaming Telemetry]
                                       |
                                       v
+----------------------------------------------------------------------+
|                Deterministic Semantic Invariants Suite               |
|  - Google Drive/Workspace soft refusal detection                     |
|  - Internal Cloud Code Interpreter (code_reference/code_stdout) leak |
|  - Conversational prose instead of tool calls                        |
|  - Tool repetition loop detection                                    |
|  - Sandbox artifact validation & schema compliance                   |
|  - Streaming TTFT & inter-chunk stall monitoring                     |
+--------------------------------------+-------------------------------+
                                       |
                                       v
           +---------------------------+---------------------------+
           |               Monitor (gemini-3.8-flash)              |
           | Evaluates full traces, proxy metrics & semantic findings |
           +-------------------------------------------------------+
```

## 2. Roles, Request Attribution & Protocols

All callers identify their traffic using custom HTTP headers:
- `X-G2A-Run`: `<run_id>` (e.g. `20261019-exp03`)
- `X-G2A-Role`: `orchestrator` | `agent` | `monitor`

### Supported Protocols:
1. **OpenAI Chat Completions (`/v1/chat/completions`):**
   - Non-streaming (`stream=False`) and SSE streaming (`stream=True`).
   - Standard tool calling format (`tools` and `tool_calls`).
   - Multimodal support via `image_url` parts.
2. **OpenAI Responses API (`/v1/responses`):**
   - The protocol used by modern agent CLIs (e.g., Codex).
   - Wire input: `{"model": "gemini-4-argon", "input": [...], "tools": [...], "stream": true|false}`.
   - Output items: `message` text and `function_call` deltas.

## 3. Data Layout & Artifacts

All run artifacts reside strictly under `runs/<run-id>/`:
```
runs/<run-id>/
├── tasks.jsonl        # Tasks generated by Orchestrator (task.schema.json)
├── argon_trace.jsonl  # Full conversational turn history, tool calls, streaming stats
├── timeline.jsonl     # Correlated timeline merging proxy debug-metrics, logs, & refresher events
├── metrics.jsonl      # Periodic metrics snapshots (TTFT percentiles, stall rates, pool status)
├── findings.jsonl     # Monitor findings & deterministic semantic invariant alerts (finding.schema.json)
└── sandbox/           # Isolated directories for tool execution with seeded fixtures
    └── <task_id>/     # Isolated sandbox root for each individual task
```

### Crash Recovery & Resume
- Every task in `tasks.jsonl` has a unique `task_id`.
- The runner checkpoints completed `task_id`s in `runs/<run-id>/completed_tasks.json`.
- On crash or restart with the same `--run-id`, the runner loads `completed_tasks.json` and skips previously executed tasks without duplicating turns or corrupting traces.

## 4. Sandbox Isolation & Mandatory Fixture Seeding

1. **Isolation Invariant:** All filesystem operations are jailed inside `runs/<run-id>/sandbox/<task_id>/`. Path traversal (`..` or root escaping) raises `SandboxViolationError`.
2. **Mandatory Fixture Seeding (`initial_files`):**
   - When tasks require reading or analyzing existing files, the Orchestrator supplies `initial_files: [{"path": "...", "content": "..."}]`.
   - The runner automatically seeds the files into the sandbox prior to Argon's first turn.
   - This eliminates synthetic path errors and model confusion caused by missing files.
3. **Realistic Imperative Paths:**
   - Prompts use standard relative workspace paths: `data/...`, `src/...`, `tests/...`, `output/...`.
   - Never use virtual remote paths like `/sandbox/...` or `/workspace/...` which trigger Google Drive refusal heuristics.
4. **Cross-Platform Tool Execution:**
   - `python_eval` executes code by writing a clean temporary file within the sandbox and invoking `sys.executable`, eliminating Windows shell quotation errors.

## 5. Deterministic Semantic Invariants

The runner executes real-time invariant checks on every turn:
1. `leaked_refusal_phrase`: Scans for Google Drive / Google Docs / Workspace refusal phrases ("permission to turn on the Google Drive app", "required Gmail settings", "I do not have access to the local sandbox filesystem", `<ElicitationsGroup>`).
2. `internal_code_interpreter_leak`: Detects leaks of Google's internal Cloud Python interpreter (`python?code_reference`, `code_stdout`, `code_stderr`).
3. `prose_refusal_instead_of_tool`: Identifies when Argon emits conversational text refusing execution when function tools were provided.
4. `tool_repetition_loop`: Detects repetitive identical tool calls without self-correction (2+ consecutive identical calls).
5. `stream_chunk_stall`: Flags inter-chunk streaming delays exceeding 15 seconds.
6. `early_stream_refusal_leak`: Detects refusal phrases leaking in initial stream chunks (up to first 500 characters) of an SSE stream.
7. `stream_error`: Flags connection drops, incomplete reads, or mid-stream socket errors.
8. `artifact_missing` / `artifact_invalid`: Verifies that files declared in `expected_behavior.expected_artifacts` exist, meet minimum size requirements, match required patterns, and comply with valid JSON syntax.

## 6. Safety Fuses & Operating Constraints

- **D3 (Strict Concurrency = 1):** Exactly ONE Argon task may be in flight at any given moment.
- **D5 (Task Ceiling):** Maximum of 20 tasks per run session unless explicitly extended.
- **Argon Timeout:** Minimum 360 seconds per Argon task (`ARGON_TIMEOUT=360`).
- **Configuration Invariant (D1):**
  - `ARGON_FALLBACK_TO_FLASH=false`: Disables silent substitution with Flash Thinking.
  - `ARGON_STALL_BREAKER_SECONDS=0`: Disables the 180s fallback circuit breaker window.
- **Kill-Switch:** Creating `STOP` or `STOP_BABYSIT` inside `runs/<run-id>/` or repository root halts all daemons within 4 seconds.
- **Auto-Stop Fuses:**
  - 5 consecutive 5xx errors from the proxy.
  - 0 active accounts detected in `/admin/status`.
